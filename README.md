# PPG-based blood pressure estimation: a leakage-free reassessment

Code, notebooks, figures and result tables of the undergraduate research project
**"Análise dos Sinais de Fotopletismografia Utilizando Inteligência Artificial"**
(PIBIC/CNPq 2025–2026, Biomedical Engineering, PUC-SP).
Author: Letícia Barboza de Godoi. Advisor: Prof. Dr. Renan Trevisoli Doria.

## What this project shows

1. **Per-record linear calibration is degenerate.** When the reference blood pressure (BP) is a
   single cuff reading replicated over every cardiac cycle of a recording, the least-squares
   slope of a per-subject calibration is forced to zero and the "calibrated" output is just the
   subject's reference reading. The resulting metrics (MAE < 4 mmHg, BHS grade A, AAMI pass)
   contain no contribution from the photoplethysmogram (PPG) or the model. Five of eleven
   calibration variants implemented in this project were affected.
2. **A trivial-baseline test detects it.** Replace the model output by noise, a constant or the
   calibration reading and check whether the metric moves.
3. **Within-subject deviation is the right target.** Reformulating the target as
   ΔBP = BP − calibration mean, with centering statistics taken only from a calibration block
   that precedes the test block and subject-wise cross-validation, a ridge model on 41 static
   morphological features explains **26.6 % of systolic and 23.7 % of diastolic** within-subject
   variance on 1,293 surgical patients (VitalDB portion of PulseDB), reducing MAE from
   12.64 to 10.72 mmHg and from 6.80 to 5.92 mmHg. The result survives permutation, leakage
   and temporal-gap controls.
4. **The label structure decides what is learnable.** The same pipeline on PTT-PPG (one cuff
   reading per record, ICC = 0.94) gives strongly negative within-subject R²; on PulseDB
   (continuous arterial reference, ICC = 0.42) it gives +0.27.

A manuscript describing these results is in preparation.

## Data (not included)

The datasets are public and must be downloaded separately. Place them under `data/` as
expected by the notebooks: `data/ptt_ppg/`, `data/pulsedb_kaggle/` and, for extracted features,
`data/pulsedb_features/`. The root path (`BASE_IC`, currently `C:\IC_PPG`) is set at the top of each
notebook and must be edited to your machine.

- **Pulse Transit Time PPG Dataset** (22 subjects, 500 Hz, ECG + PPG, cuff BP per record).
  Mehrgardt et al., PhysioNet, v1.1.0, doi:10.13026/jpan-6n92.
  `python scripts/download_pulsedb.py` downloads PulseDB; PTT-PPG is fetched with `wfdb`.
- **PulseDB, VitalDB portion** (CalBased test subset: 1,293 subjects × 40 segments of 10 s at 125 Hz,
  reference BP from arterial line). Wang et al., Front. Digit. Health 4:1090854, 2023,
  doi:10.3389/fdgth.2022.1090854. Redistribution used: Kaggle
  `weinanwangrutgers/pulsedb-balanced-training-and-testing`, version 4.

Both datasets are de-identified; no new human-subject data were collected.

## Reproducing the main result

1. Download the PulseDB CalBased subset (see above).
2. Run `notebooks/14_corrected_reextraction_pulsedb.ipynb` to extract the 41 features with
   foot-to-foot segmentation (writes `features_pulsedb_calbased_test_v3.csv`, ~330 MB).
3. Run `notebooks/13_within_subject_delta_pulsedb.ipynb`. Every table and figure in
   `results/pulsedb/nb13_*` and `figures/notebooks/nb13_*` is regenerated.

## Evaluation protocol in one paragraph

Subject-wise 5-fold partition with a fixed seed. For each subject, the first 20 segments form
the calibration block and the last 20 the test block. Features and targets are centered using
the calibration block only. Models are trained on calibration-block data of training-fold
subjects and applied to test-block data of held-out subjects. The mandatory baseline predicts
ΔBP = 0 (R² = 0 by construction). Confidence intervals come from bootstrap over whole subjects;
the negative control permutes labels within subject and retrains the full pipeline 1,000 times.
